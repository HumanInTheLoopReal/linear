# Contributing

Bug reports, fixes, and new commands are all welcome. This page covers the
mechanics. [`AGENTS.md`](AGENTS.md) documents the architecture and the
invariants a change must not break, and
[`AGENT_INSTRUCTIONS.md`](AGENT_INSTRUCTIONS.md) is the operational deep
dive.

## Setup

Node.js 22 or newer, npm, and network access.

```bash
git clone https://github.com/HumanInTheLoopReal/linear.git
cd linear
npm install
```

`npm install` triggers `prepare`, which regenerates the GraphQL types from
Linear's published schema and installs the git hooks. It needs network
access but no API token.

## Gates

Run all four before you commit. CI runs the same four, so a local failure is
a guaranteed CI failure.

```bash
npm run check:ci     # Biome format and lint, no auto-fix
npx tsc --noEmit     # strict TypeScript
npm test             # Vitest unit suite
npm run build        # codegen, compile, regenerate USAGE.md
```

`npm run check` is the auto-fixing variant, useful while iterating.

Integration tests (`npm run test:integration`) need `LINEAR_API_TOKEN` and a
real workspace. They skip themselves when the token is absent, so they never
block local work.

Two rules that catch people out: never hand-edit `src/gql/`, it is
generated by `npm run generate`; and never commit `USAGE.md`, it is
generated during the build and git-ignored.

## Tests

Mock one layer deep. Every new function wants at least a happy path and its
primary error case.

| Testing a | Mock | Lives in |
| --- | --- | --- |
| Resolver | `LinearSdkClient` | `tests/unit/resolvers/` |
| Service | `GraphQLClient` | `tests/unit/services/` |
| Command | Both, via a fake context | `tests/unit/commands/` |
| Common | Nothing, they are pure | `tests/unit/common/` |

## Commits

Conventional Commits, enforced by commitlint through a git hook:

```
<type>(<scope>): <subject>
```

Types in use: `feat`, `fix`, `refactor`, `chore`, `docs`, `test`, `build`,
`ci`, `style`, `perf`. Subject lines need at least 10 characters and scopes
are lower case.

Do not add `Co-authored-by:` trailers for AI assistants. Human co-authors
are fine.

## Pull requests

Work on a branch, push it, and open a pull request against `main`. Name
branches in kebab case, for example `fix-prepare-commit-trailer`. Direct
pushes to `main` are reserved for releases and narrow operational fixes such
as a typo or a broken link. When in doubt, open a pull request.

Maintainers: the release runbook is [`RELEASING.md`](RELEASING.md).
