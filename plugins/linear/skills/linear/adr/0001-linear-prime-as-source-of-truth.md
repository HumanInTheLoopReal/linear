# ADR-0001: Use linear prime as CLI Reference Source of Truth

## Status

Accepted

## Context

A skill for a CLI tool will, by default, inline the CLI reference into its SKILL.md and resource files. For the linear skill that would mean duplicating CLI documentation across:

- `SKILL.md` inline (potentially thousands of words of command reference)
- `resources/CLI_REFERENCE.md` (already exists as a deep-dive doc)
- Scattered examples throughout the other resource files

This creates:
- **Duplication**: Same commands documented two or three times.
- **Drift risk**: Documentation falls behind `linear` releases as flags / verbs evolve.
- **Token overhead**: Thousands of tokens loaded even for simple operations.

Meanwhile, `linear` already ships first-class self-describing surfaces:

- `linear prime` outputs an AI-optimized workflow brief (designed to be injected into Claude `SessionStart` / `PreCompact` hooks).
- `linear <command> --help` provides specific per-command usage via Commander.js.
- `USAGE.md` (generated by `npm run generate:usage` from per-domain `DomainMeta` exports) is the canonical full reference.

All three update automatically with every `linear` release.

## Decision

Use `linear prime` as the single source of truth for CLI commands:

1. **SKILL.md** contains only value-add content (process invariants, classification gate, reference router, mutation safety, and pointers to `linear prime` and `linear --help`). It does **NOT** contain inline CLI-command reference.
2. **CLI reference** points to `linear prime` (auto-loaded by SessionStart / PreCompact hooks per the plugin manifest) and `linear <cmd> --help`.
3. **References** provide the canonical operating model. **Resources** retain advanced CLI concepts. Neither duplicates command syntax.

## Consequences

### Positive

- **Zero CLI-doc maintenance**: command reference auto-updates with `linear` releases via `linear prime` + `--help` + `USAGE.md`.
- **DRY**: single source of truth.
- **Accurate**: no version drift possible — the documentation IS the code.
- **Router-shaped SKILL.md**: the always-loaded body remains a map rather than ballooning into a manual.

### Negative

- **Dependency on `linear prime` output format**: if the brief shape changes significantly, this skill may need adaptation.
- **External tool requirement**: the skill assumes `linear` is installed and on PATH (the Prerequisites section in SKILL.md surfaces this).

## Implementation

Files restructured under this ADR:

- `SKILL.md` — process router with no inline CLI reference.
- `references/*.md` — one canonical process concern per file.
- `resources/CLI_REFERENCE.md` — a compact summary, not a replication of `linear prime`. Encourages the reader to run `linear prime` for the live brief and `linear <cmd> --help` for per-command detail.
- `CLAUDE.md` (skill maintenance guide) — codifies the DRY-via-linear-prime principle and provides a what-belongs-in-resources decision table for future maintainers.
- Plugin manifest `plugins/linear/.claude-plugin/plugin.json` — wires `linear prime` into the `SessionStart` and `PreCompact` hooks so the brief auto-loads at the points where context is freshest / about to be lost.
